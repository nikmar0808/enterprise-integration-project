Step 3: Test 2 – Simulating an Enterprise Failure (The Constraint Check)
Now, let's intentionally simulate a malicious or broken payload common in legacy grid systems to see how Pydantic protects your system boundaries.

Modify the text inside the input box to break three strict constraints:
1. Make the meter_id only 2 characters long ("M1") (Violates: min_length=5).
2. Make a kwh_value negative (-5.5) (Violates: gt=0.0).
3. Make a voltage value too low (80.0) (Violates: ge=100.0).

Your broken payload text should look like this:

{
  "meter_id": "M1",
  "grid_zone": "NORTH-UTILITY-GRID",
  "readings": [
    {
      "timestamp": "2026-07-28T09:00:00Z",
      "kwh_value": -5.5,
      "voltage": 80.0
    }
  ]
}

Click the blue "Execute" button again.

The Result:
The server will reject the request instantly with a 422 Unprocessable Entity response. If you look at the response body, Python prints a highly detailed schema error report telling you exactly which field failed, what the input was, and what rule it violated (e.g., String should have at least 5 characters, Input should be greater than 0).

Notice that you did not write a single conditional if/else block or loop inside your code to catch those errors. The framework intercepts the bad transmission at the network interface boundary and handles the validation automatically.
